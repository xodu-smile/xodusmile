# 1. 서론

랜섬웨어는 오늘날 가장 파괴적이고 보편화된 사이버 위협이다. 공격자는 피해자의
파일을 강제로 암호화한 뒤 복구 대가로 금전을 요구하며, 최근에는 데이터 유출과
암호화를 함께 협박하는 **이중 갈취(double extortion)** 로 진화하고 있다. 공격
도구가 서비스형 랜섬웨어(RaaS, Ransomware-as-a-Service) 형태로 거래되면서 기술
수준이 낮은 공격자도 손쉽게 신종 변종을 생산·배포할 수 있게 되었고, 그 결과
하루에도 수많은 변종이 새롭게 등장한다.

이러한 환경에서 기존의 **시그니처(signature) 기반 백신**은 구조적인 한계를
드러낸다. 시그니처 방식은 *이미 알려진* 악성코드의 해시·패턴을 데이터베이스에
등록해 두고 일치하는 파일을 차단하는 방식이므로, 데이터베이스에 등록되지 않은
신종·변종(=제로데이) 랜섬웨어에는 사실상 무력하다. 공격자가 코드 일부만 바꾸거나
패킹(packing)만 다시 해도 시그니처가 달라져 탐지를 우회할 수 있다.

따라서 *"파일이 무엇인가(what it is)"* 가 아니라 *"프로세스가 무엇을 하는가(what
it does)"* — 즉 **실시간 행위(behavior)** 를 분석하여 랜섬웨어 고유의 악성 행동
패턴(대량 암호화, 섀도카피 삭제, 협박문 살포 등)을 포착하고 차단하는 **행위 기반
탐지 기술**의 필요성이 크게 증가하고 있다. 본 과제는 이 문제의식에서 출발하여,
신종 랜섬웨어까지 탐지·차단할 수 있는 행위 기반 EDR 솔루션을 직접 설계·구현하는
것을 목표로 한다.

## 1-1. 프로젝트 배경

- **시그니처 기반 탐지의 본질적 한계.** 시그니처 탐지는 "알려진 악성코드"만
  막을 수 있다. 신종 랜섬웨어는 시그니처가 만들어져 배포되기 전까지 무방비
  구간(window of exposure)에 노출된다. 백신 벤더가 검체를 수집→분석→시그니처
  배포하는 데 걸리는 시간 동안 피해는 이미 발생한다.

- **제로데이(Zero-day) 대응 부족.** 사용자 정의 패커·다형성(polymorphism)·
  코드 난독화로 무장한 변종은 동일한 악성 행위를 하면서도 매번 다른 바이너리
  외형을 가진다. 정적 분석만으로는 이를 추적할 수 없다.

- **공격 기법의 고도화 — "정상 도구의 무기화(LotL)".** 최신 랜섬웨어는 자체
  암호화 코드를 들고 오는 대신 Windows에 내장된 정상·서명 도구를 암호화 엔진으로
  악용한다(Living-off-the-Land). `cipher /e`(EFS 암호화), `manage-bde`(BitLocker
  강제 암호화), `certutil`·`bitsadmin`(LOLBin 페이로드 운반) 등이 대표적이다.
  실행 파일 자체가 정상 서명 도구이므로 시그니처·평판 기반 방어로는 잡히지 않는다.

- **결론.** 이상의 배경에서, 파일의 정적 특징이 아니라 **런타임에 발생하는
  파일 I/O·프로세스·레지스트리 행위**를 실시간으로 관찰하고 그 *조합과 강도*로
  악성 여부를 판정하는 행위 기반 실시간 탐지 기술이 요구된다. RansomGuard EDR는
  이 요구에 대한 직접적인 응답이다.

## 1-2. 기존 한계점

| 구분 | 기존 방식의 한계 | 본 과제의 대응 방향 |
|---|---|---|
| **탐지 범위** | 시그니처 미등록 신종·변종 탐지 불가 | 행위 패턴 기반 → 외형이 달라도 *행동*으로 탐지 |
| **탐지 지연** | 검체 수집→시그니처 배포까지 무방비 구간 | 엔드포인트에서 실시간 관찰·즉시 대응 |
| **오탐(False Positive)** | 단순 휴리스틱은 정상 작업(압축·백업)을 오탐 | 슬라이딩 윈도우 점수 합산 + 운영자 허용목록 + 행위자 신뢰 게이트로 오탐 억제 |
| **탐지 회피** | 사용자 모드 후킹은 우회·무력화 가능, PEB 위조로 커맨드라인 은닉 | 커널 미니필터·커널 콜백으로 위조 불가능한 *지상 진실(ground-truth)* 확보 |
| **자기 보호** | 보안 프로세스 자체가 종료당하면 무력화 | `RtlSetProcessIsCritical`·커널 `ObCallback` 핸들 보호·watchdog 상호 감시 |
| **사후 대응** | 탐지만 하고 차단·격리는 사람 손에 의존 | 점수 임계 초과 시 커널 격리 + 프로세스 자동 종료 |

특히 **신종 랜섬웨어**에 대해 기존 방식은 ① 시그니처가 없어 탐지 자체가 안 되거나,
② 뒤늦게 시그니처가 배포되어 *탐지 지연* 동안 이미 다수 파일이 암호화되거나,
③ 회피를 위해 정상 프로세스에 인젝션·위장한 경우 신뢰 프로세스라는 이유로
*오탐 억제 로직에 의해 오히려 탐지에서 면제*되는 사각지대를 만든다. 본 과제는
이 세 가지를 핵심 공략 지점으로 삼았다.

## 1-3. 과제 목표

**목표:** 실시간 행위 분석을 통해 *알려지지 않은 신종 랜섬웨어까지* 탐지하고,
피해가 확산되기 전에 자동으로 차단(격리·종료)하는 엔드포인트 보안 솔루션을
개발한다.

### 세부 목표

1. **다중 행위 신호 융합 탐지** — 단일 지표가 아니라 카나리·엔트로피·대량 I/O·
   협박문·프로세스 명령어·레지스트리 변조 등 **서로 독립적인 행위 신호**를 수집하고
   슬라이딩 윈도우 가중치 합산으로 종합 판정한다.
2. **커널 레벨 지상 진실 확보** — 커널 모드 미니필터로 모든 볼륨의 파일
   생성·쓰기·이름변경을 가로채, 사용자 모드 우회·PEB 위조로도 숨길 수 없는
   탐지 근거를 확보한다.
3. **실시간 자동 차단** — 임계 점수 초과 시 커널 내에서 후속 쓰기/이름변경을
   차단하고 의심 프로세스를 즉시 종료한다(`off`/`quarantine`/`kill` 3단계 정책).
4. **오탐 최소화** — 정상 백업·압축·동기화 작업을 랜섬웨어로 오인하지 않도록
   운영자 허용목록·행위자 신뢰 게이트·내용 기반 협박문 검증을 적용한다.
5. **운영·포렌식 기능** — Flask 대시보드, MITRE ATT&CK 기법 매핑, Markdown
   사건 보고서, SQLite 이벤트 스토어, SIEM/Webhook 통합을 제공한다.

### 과제 범위와 한계(명시적 스코프)

- **대상 OS:** Windows 11 (22H2 이상, x64/ARM64). 커널 드라이버는 Windows 전용.
  사용자 모드 에이전트는 Linux/macOS에서도 동작하나 커널 신호는 받지 못한다.
- **성격:** **연구·학습용 프로토타입**이다. 상용 백신을 대체하는 제품이 아니라,
  행위 기반 탐지의 원리와 효과를 검증하는 PoC(Proof of Concept)다.
- **명시적 비(非)목표:** 이미 암호화가 *완료된* 파일의 복호화, 백업 솔루션,
  중앙 관리 콘솔(fleet)·RBAC/SSO·서명된 MSI 자동배포는 본 과제 범위에 포함하지
  않는다(로드맵으로 별도 정의). 본 솔루션은 *탐지·확산 차단*에 집중하며, 탐지
  *지연(latency)* 동안 발생하는 초기 소수 파일의 암호화는 원리상 완전히 막을 수
  없다(7-2 한계점 참조).

# 2. 이론적 배경

## 2-1. 랜섬웨어의 동작 원리

전형적인 크립토(crypto) 랜섬웨어의 공격 생애주기는 다음과 같다.

1. **초기 침투 및 실행** — 피싱 첨부파일·취약점·RDP 등으로 침투해 페이로드 실행.
2. **방어 무력화 및 복구 차단** — 탐지·복구를 막기 위해 사전 작업을 수행한다.
   - 볼륨 섀도카피(VSS) 삭제: `vssadmin delete shadows`, `wmic shadowcopy delete`
     → 윈도우 자체 복구 지점 제거 (MITRE **T1490 Inhibit System Recovery**).
   - 부팅 복구 비활성화: `bcdedit /set recoveryenabled no`.
   - 백신 무력화: Defender 실시간 보호 해제, 서비스 중지, 예외 등록.
   - 로그 삭제(anti-forensics): `wevtutil cl`, 이벤트 로그 클리어.
3. **대량 암호화(핵심 피해 단계)** — 사용자 문서를 빠르게 순회하며 각 파일을
   읽어 암호화 후 덮어쓰고(또는 새로 쓰고 원본 삭제) 확장자를 변경한다
   (MITRE **T1486 Data Encrypted for Impact**). 이 단계의 행위적 특징:
   - **고엔트로피 쓰기** — 암호문은 통계적으로 난수에 가까워 바이트 분포가 균등해진다.
   - **매직바이트 소실** — PE/PDF/Office/JPEG 등 알려진 파일 헤더가 식별 불가로 변한다.
   - **대량·고속 파일 변경(burst)** — 짧은 시간에 다수 파일이 수정·이름변경된다.
   - **랜섬 확장자** — `.encrypted`, `.locked`, `.wcry` 등으로 일괄 rename.
4. **협박문 살포** — 각 폴더에 `HOW_TO_DECRYPT.txt`, `_readme.txt`, `.hta` 등
   복구 안내·결제 요구 파일을 떨어뜨린다.
5. **(선택) 데이터 유출** — 이중 갈취를 위해 `rclone`·압축 스테이징으로 외부 반출.

## 2-2. 행위 기반 탐지(Behavior-based Detection)

행위 기반 탐지는 파일의 정적 외형이 아니라 **프로세스가 실행 중에 일으키는
행위**를 관찰한다. 위 2-1의 각 단계는 *외형은 매번 달라도 행위 패턴은 보존되는*
랜섬웨어의 본질적 특징이다. 따라서 다음과 같은 행위를 신호(signal)로 포착하면
신종·변종도 탐지할 수 있다.

- 파일 I/O 행위: 엔트로피 급증, 매직바이트 소실, 대량 rename/write burst.
- 프로세스 행위: VSS 삭제·BCD 변조 명령 실행, LOLBin 부모-자식 체인, 시스템
  바이너리 위장(예: `%TEMP%\svchost.exe`).
- 레지스트리 행위: Defender 키 변조, Run 키 지속화, IFEO 하이재킹.
- 미끼(deception) 행위: 사용자가 절대 건드리지 않을 **카나리 파일**의 변조.

**핵심 설계 원칙은 "단일 신호로 단정하지 않는다"** 이다. 정상 작업(대용량 압축,
디스크 암호화 백업 등)도 일부 신호를 유발할 수 있으므로, 여러 독립 신호를 일정
시간 윈도우 안에서 가중 합산하여 *조합과 강도*로 판정한다(2-4 참조).

## 2-3. 엔트로피 분석(Entropy Analysis)

정보 이론의 **섀넌 엔트로피(Shannon Entropy)** 는 바이트 분포의 무질서도를
0~8 bit/byte 범위로 정량화한다.

```
H(X) = - Σ  p(xᵢ) · log₂ p(xᵢ)        (xᵢ = 0..255 바이트 값)
```

- 일반 텍스트/구조화 문서: 낮은~중간 엔트로피(약 3~6).
- 암호화·압축 데이터: 8에 근접하는 매우 높은 엔트로피(난수에 가까움).

랜섬웨어가 파일을 암호화하면 엔트로피가 급격히 상승한다. 본 솔루션은 파일
샘플(최대 4 KB)의 엔트로피가 **임계치(7.5, 카나리 트립 후 부스트 모드에서는 6.8)**
이상이면서, 알려진 매직바이트가 인식되지 않고, 대상이 사용자 문서류 확장자인
경우에만 `high_entropy_write` 신호를 발생시킨다. **압축·미디어 파일은 원래부터
엔트로피가 7.5+** 라는 점이 오탐의 원인이 되므로, 이런 형식(zip/jpg/mp4 등)은
엔트로피 단독 신호에서 아예 제외하고 매직바이트 *소실*·확장자 *변경*·대량 burst
같은 **변화 기반** 신호로만 본다. 즉 엔트로피는 단독 판정 근거가 아니라 여러
독립 신호와의 *조합*으로만 고위험 판정에 기여한다.

## 2-4. 시간 윈도우 가중치 합산(Sliding-Window Scoring)

각 신호는 `weight`(가중치)와 `severity`(심각도)를 가지며, **120초 슬라이딩
윈도우** 안의 모든 신호 점수를 합산해 현재 위협 등급을 산출한다. 오래된 신호는
2분 후 자동 만료되어 "과거의 일로 계속 경보가 울리는" 현상을 방지한다.

| 누적 점수 | 등급 | 의미 |
|---|---|---|
| 0 ~ 29 | INFO | 정상 |
| 30 ~ 59 | LOW | 약간 의심 |
| 60 ~ 99 | MEDIUM | 주의 |
| 100 ~ 149 | HIGH | 위험 |
| 150 이상 | CRITICAL | 즉시 대응 |

## 2-5. 커널 미니필터(Kernel Mini-Filter Driver)

Windows의 **파일시스템 미니필터**는 파일시스템 스택에 끼어들어 모든 파일 I/O를
가로채는 커널 드라이버다. 사용자 모드 후킹과 달리 ① 우회·무력화가 어렵고,
② 커맨드라인을 커널 메모리에서 직접 취득하므로 PEB 위조로 숨길 수 없으며,
③ 후속 I/O를 **커널 내에서 즉시 차단**할 수 있다. RansomGuard는 미니필터에
더해 프로세스 생성 콜백(`PsSetCreateProcessNotifyRoutineEx`), 레지스트리 콜백
(`CmRegisterCallbackEx`), 핸들 보호 콜백(`ObRegisterCallbacks`)을 결합하여
*위조 불가능한 지상 진실*과 *자기 보호*를 동시에 확보한다.

## 2-6. MITRE ATT&CK 프레임워크

전 세계 보안 업계가 공유하는 공격 기법 분류 체계다. 본 솔루션은 모든 탐지 신호를
표준 기법 ID로 매핑하여(`T1486` 데이터 암호화, `T1490` 시스템 복구 무력화,
`T1055` 프로세스 인젝션, `T1036.005` 시스템 바이너리 위장, `T1218` LOLBin 등)
보고서·대시보드에 표기, SOC/IR 팀의 위협 인텔리전스 연계를 용이하게 한다.

## 4-1. 단계별 행위 분석 로직

### (1) 데이터 수집 — Detectors
모든 탐지기는 `Detector` 추상 클래스를 상속하고 데몬 스레드로 동작하며,
`emit(Signal)`로 엔진에 신호를 보낸다. 한 탐지기의 크래시가 다른 탐지기로
전파되지 않도록 `_run_safe()`로 예외를 격리한다.

- **커널 출처(위조 불가):** `minifilter_bridge`가 `RansomGuard.sys`로부터
  `(pid, path, op, bytes)` 이벤트를 받아 PID별 write/rename burst를 집계,
  `process_kernel`·`registry_kernel`이 커널 콜백 이벤트를 구독.
- **사용자 모드:** `canary`(미끼 파일 SHA-256 폴링), `mass_io`(엔트로피·매직바이트·
  burst), `ransom_note`(협박문 내용 분석), `process_cmdline`(WMI 명령어 룰),
  `process_watcher`(psutil 폴링·프로세스 위장·LOLBin 체인).

### (2) 분석 — 신호 가중치화

각 탐지기는 행위의 위험도에 따라 가중치와 심각도를 부여한다(발췌).
가중치는 **"정상 소프트웨어가 이 행위를 할 확률"** 을 기준으로 5개
티어(텔레메트리 1~5 / 약한 정황 8~25 / 의심 패턴 30~45 / 사보타주 50~70 /
지상 진실 80~90)로 위계화했고, "어떤 증거 조합이 어느 등급(30/60/100/150)에
도달해야 하는가"라는 보정 시나리오로부터 역산했다. **신호 전체(40여 종)의
수치별 상세 근거는 부록 `docs/DESIGN_RATIONALE.ko.md`** 에 신호 단위로
정리했다.

| 신호 | weight | severity | 발화 조건 | ATT&CK |
|---|---:|---|---|---|
| `canary_modified/deleted` | 80 | CRITICAL | 미끼 파일 변경/삭제 | T1486 |
| `ransom_note_spread` | 90 | CRITICAL | 내용 확인 협박문이 3개+ 폴더 확산 | T1486 |
| `ransom_note_dropped`(내용 확인) | 45 | HIGH | 지갑주소·onion 등 강 지표 포함 단일 노트 | T1486 |
| `kernel_blocked_op` | 60 | HIGH | 격리 PID의 차단된 커널 작업 | T1486 |
| `kernel_write_burst` | 35 | HIGH | PID별 4초 내 75MB+ 쓰기 | T1486 |
| `kernel_rename_burst` | 40 | HIGH | PID별 5초 내 20회+ rename | T1486 |
| `magic_bytes_lost` | 12 | HIGH | 알려진 헤더가 인식 불가로 변함 | T1486 |
| `high_entropy_write` | 8 | MEDIUM | 엔트로피 ≥ 7.5 + 매직 미인식 + 문서류 확장자 | T1486 |
| `modify_burst` | 25 | HIGH | 10초 내 암호화 특징 이벤트 15개+ | T1486 |
| `suspicious_extension` | 15 | HIGH | `.encrypted`/`.locked` 등으로 rename | T1486 |
| `process_masquerade` | 60 | HIGH | 시스템명 위장 실행(`%TEMP%\svchost.exe`) | T1036.005 |
| `vssadmin_delete_shadows` | 70 | CRITICAL | VSS 섀도카피 삭제 | T1490 |
| `defender_disable_realtime` | 55 | HIGH | Defender 실시간 보호 해제 | T1562.001 |
| `ransomguard_service_tamper` | 80 | CRITICAL | 자기 서비스 레지스트리 변조(EDR 무력화 시도) | T1562.001 |
| `file_delete` | 3 | LOW | 단일 삭제(같은 PID 의 암호화 동반 시에만 채점) | T1070.004 |

가중치 산정 예시 — *왜 카나리는 80인가*: 지상 진실 신호 1개 + 약한 정황
1개(매직 소실 12, burst 25 등)가 HIGH(100)에 도달하도록 80 이상이어야
하고, 사용자가 미끼 파일을 실수로 건드리는 드문 사고가 존재하므로 단독
으로 HIGH 를 넘지 않게 100 미만이어야 한다 — 이 연립조건의 해가 80이다.
*왜 VSS 삭제는 70인데 severity 는 CRITICAL 인가*: weight(점수 기여)와
severity(단발 대응 트리거)는 분리된 채널이다. 관리자가 정말로 섀도를
지우는 드문 정상 사례가 있어 점수 단독으로 CRITICAL(150)을 만들지는
않지만, 행위 자체는 즉시 대응(해당 PID + 부모 종료)을 검토할 가치가
있으므로 severity 는 CRITICAL 이다.

### (3) 판단 — ScoringEngine + 신뢰 게이트
- **합산·만료:** `submit()`이 신호를 추가하고 120초 초과 신호를 제거한 뒤 모든
  리스너에 `(signal, score, level)`을 통지.
- **행위자 신뢰 게이트(`actor_trust.py`)** — *점수 입력 단계*에서 게이팅한다.
  신호를 유발한 PID가 **디스크상 검증된 이미지 경로** 기준 신뢰 시스템 컴포넌트
  (Defender/서비싱/WMI 등, System32 등 쓰기 보호 경로)이면 점수에 기여하지 않아
  유휴 머신의 정상 OS 작업이 점수를 부풀리는 문제를 차단. **경로 검증 실패 시
  fail-closed**(정상 채점)로 탐지 누락을 방지.
- **신뢰 게이트 사각지대 차단(핵심)** — `GROUND_TRUTH_ENCRYPTION` 집합
  (`canary_*`, `magic_bytes_lost`, `suspicious_extension`, `ransom_note_spread`,
  `kernel_blocked_op`)에 속한 신호는 **신뢰 게이트로 절대 면제되지 않는다.**
  즉, 신뢰 프로세스(svchost 등)에 인젝션·위장된 랜섬웨어가 실제 암호화(=지상
  진실)를 일으키면 신뢰 면제를 무시하고 항상 채점한다.

### (4) 대응 — ProcessResponder
- **모드:** `off` / `quarantine`(커널 격리만) / `kill`(격리 + 종료).
- **정밀 종료(corroboration):** PID가 명시된 HIGH/CRITICAL 신호만 처리.
  CRITICAL 단독은 고신뢰로 즉시 대응, **HIGH는 보강 증거 필요** — 윈도우 내 실제
  암호화 활동 또는 *동일 PID를 가리키는 서로 다른 탐지기 2개 이상*. (과거의 점수
  기반 전체 PID 일괄 종료는 오탐을 대량 피해로 키워 폐지.)
- **시스템 핵심 보호:** `NEVER_KILL`(lsass/csrss/python 등)은 절대 종료하지 않는다.
- **종료 전략:** `psutil.kill()` 우선, 실패 시 ctypes `OpenProcess(PROCESS_TERMINATE)
  + TerminateProcess` 폴백.

| **대응(Respond)** | `responder.py`, `incident_report.py`, `tamper.py` | 격리·종료, 사건 보고서·알림, 자기 보호 |

## 5-2. 구현 과정 (탐지 알고리즘 설계 및 임계치 조정)

본 과제의 핵심 난제는 **"탐지율은 높이되 오탐은 낮추는"** 균형점을 찾는 것이었고,
이는 알고리즘 설계와 임계치 조정의 반복으로 해결했다.

1. **엔트로피·burst 임계치 산정.** 시뮬레이터로 정상 문서를 채운 뒤 암호화
   패턴을 주입하며 측정한 결과, 엔트로피 임계 **7.5**, burst **10초/15파일**,
   커널 write burst **4초/75MB**, rename burst **5초/20회**로 확정했다.
   카나리 트립 시 30초간 임계를 공격적으로 낮추는(엔트로피 7.5→6.8, 가중치 ×1.5)
   **크로스 신호 부스트**를 도입해 암호화 진행 중 민감도를 끌어올렸다.

2. **오탐 억제 — 3중 게이트.** 초기에는 유휴 머신에서도 정상 OS 작업이 점수를
   CRITICAL로 부풀리는 문제가 있었다. 이를 ① **행위자 신뢰 게이트**(신뢰 시스템
   프로세스의 신호는 점수 미반영), ② **운영자 허용목록**(Veeam/Acronis/7-Zip 등
   이름·경로 등록), ③ **협박문 내용 검증**(이름만 매칭된 단발 노트는 MEDIUM 힌트로만,
   암호화폐 지갑·`.onion`·협박 문구 등 *내용 확인*된 노트만 HIGH/CRITICAL로 승격)
   으로 해결했다.

3. **사각지대 보강.** 단, 위 오탐 억제가 *새로운 사각지대*를 만들지 않도록
   `GROUND_TRUTH_ENCRYPTION`·`_NEVER_EXEMPT_SIGNALS` 집합을 두어, 카나리 변조·
   협박문 확산·Defender 자기 비활성화 같은 고신뢰 신호는 신뢰 게이트·허용목록으로도
   **면제 불가**하도록 설계했다.

4. **정밀 종료 로직.** "점수 기반 전체 PID 일괄 종료"는 오탐 1건이 다수 정상
   프로세스 종료로 번지는 위험이 있어 폐지하고, **PID 명시 + corroboration**
   (CRITICAL 단독 또는 HIGH+2개 탐지기/암호화 동반) 기반의 정밀 종료로 전환했다.

5. **명령어 룰셋 확장(22→33).** VSS/BCD/Defender 무력화에 더해 LOLBin·LotL
   계열 11개 룰(`cipher /e`, `manage-bde -on`, `certutil`, `bitsadmin`,
   `esentutl`, `wmic process call create`, `sc create type=kernel`(BYOVD),
   `7z -p`/`rclone`)을 추가해 "정상 도구 무기화" 공격을 포착하도록 했다.

## 5-3. 솔루션 실행 (사용자 알림 및 로그 기록 시스템)

탐지 결과는 **즉시 알림 + 영구 기록 + 시각화**의 3채널로 전달된다.

- **사건 보고서(`incident_report.py`).** 실제 대응(격리/종료)이 발생한 경우에만
  (no-op은 스킵) Markdown 보고서 1건을 생성: *프로세스 헤더 → 대응 내역 → 위협
  컨텍스트(ATT&CK) → 해당 PID 기여 신호 → 최근 윈도우 → 원본 액션 JSON*.
  파일명은 `incident_<일시>_pid<N>_<이름>.md`.
- **데스크톱 알림.** 백그라운드 스레드에서 OS별 디스패치(Windows: win10toast →
  BurntToast → MessageBoxW 폴백). 알림 폭주로 데스크톱이 멈추던 문제를 디바운스·
  검은 화면 깜빡임 제거로 개선했다.
- **이벤트 스토어(`event_store.py`).** 모든 신호를 SQLite `signals` 테이블에
  `score_after/level_after`와 함께 동기 기록 → 탐지 타임라인·지연의 포렌식 근거.
- **Flask 대시보드(`dashboard/app.py`).** `http://127.0.0.1:5000` 에서 실시간
  점수·최근 이벤트·프로세스 목록·대응 로그·수동 kill/release 버튼·관리자 패널
  (모드 전환, PID별 위협 분석, 허용목록 편집)을 제공. 토큰(`X-API-Key`/`Bearer`)
  설정 시 변경성/관리자 API에 인증을 요구하며 `/api/heartbeat`만 항상 공개.
- **자동 위협등급 복구.** 원인 프로세스가 종료되면 해당 PID 기여 신호를 만료시켜
  위협 등급을 자동으로 정상 복구(잔류 경보 방지).
- **(기업) SIEM/Webhook(`integrations.py`).** HIGH 이상 이벤트를 CEF over syslog
  (Splunk/QRadar/Sentinel) 및 JSON Webhook(Slack/Teams/PagerDuty)으로 비동기
  전송. **fail-open** — 통합 장애가 탐지 핫패스를 막지 않는다.

# 6. 과제 실험

## 6-1. 과제 환경 (격리 실험 환경 구축)

실검체 랜섬웨어는 watch 디렉터리 밖 시스템 전체를 암호화해 VM을 부팅 불능으로
만들 수 있으므로, 실험은 **네트워크가 격리되고 스냅샷이 있는 전용 VM**에서만
수행했다.

- **게스트:** Windows 11 (22H2+) x64 일회용 VM, 스냅샷 가능.
- **네트워크 격리:** 어댑터를 Host-only/Internal로 설정(NAT·브리지 금지),
  공유 폴더·클립보드·드래그앤드롭 전면 차단.
- **드라이버:** 테스트 서명 활성화(`bcdedit /set testsigning on`) 후 미니필터
  빌드·설치, `fltmc filters`로 적재 확인. (커널 차단 미검증 시 `--no-minifilter`.)
- **자동화 도구:** `scripts/lab.ps1` 오케스트레이터가 8단계(경로 등록 → 드라이버
  → 에이전트 실행 → pre-flight GO/NO-GO → 스냅샷 → detonate → postmortem → 복원)를
  묶되, **스냅샷 촬영과 검체 실행은 사람이 직접** 하도록 안전 게이트를 유지.
- **사전 점검(`lab_preflight.ps1`):** VM·네트워크 격리·공유 채널·testsigning·
  Defender 실시간 보호·드라이버/에이전트 로드·디코이·스냅샷을 GO/NO-GO로 검증
  (BLOCKER 존재 시 NO-GO로 차단).
- **성적 집계(`postmortem.py`, `scan_damage.py`):** 검체가 에이전트를 죽이거나
  BSOD가 나도 동작하도록 *디스크에 영속된 증거*만 읽는다 — `detector.db`(탐지
  타임라인·지연), `reports/*.md`(실제 대응), watch dir 스캔(피해 파일 수).
  프로젝트 모듈을 import하지 않아 에이전트 코드가 깨져도 집계가 가능하다.

## 6-2. 랜섬웨어 실험 (악성 행위 탐지)

다양한 공격 시나리오에 대해 탐지·차단 성능을 검증했다. 안전을 위해 1차적으로는
**행위 시뮬레이터(`tests/simulator.py`, `demo_inproc.py`)** 로 실제 `vssadmin`/
`bcdedit`을 실행하지 않고 동일한 행위 신호를 주입했고, 2차로 격리 VM에서 실검체를
detonate하여 권한상승·전파 등 부가 행위를 관찰했다.

| 시나리오 | 주입/재현 행위 | 기대 탐지(신호) | 매핑 ATT&CK |
|---|---|---|---|
| `populate`→`encrypt` | 더미 문서 생성 후 난수 덮어쓰기 + `.encrypted` rename | `high_entropy_write`, `magic_bytes_lost`, `suspicious_extension`, `modify_burst` → HIGH/CRITICAL | T1486 |
| `canary` | 카나리 파일에 NUL 바이트 append | `canary_modified` 단발 → CRITICAL | T1486 |
| `vss` | `vssadmin delete shadows /all /quiet` 주입 | `vssadmin_delete_shadows` → HIGH | T1490 |
| `bcd` | `bcdedit /set recoveryenabled no` 주입 | `bcd_recovery_disable` → HIGH | T1490 |
| `stealth` | burst 임계를 회피하는 *저속* 암호화 | burst는 회피하나 엔트로피·매직·확장자 신호로 여전히 탐지 | T1486 |
| 협박문 확산 | 무작위 이름 노트(`A7F3C.txt`)에 지갑주소·`.onion`·협박문구 | `ransom_note_spread`(3폴더+) → CRITICAL | T1486 |
| 프로세스 위장 | `%TEMP%\svchost.exe` 실행 | `process_masquerade` → HIGH | T1036.005 |
| LotL 무기화 | `cipher /e`, `manage-bde -on`, `certutil`/`rclone` | 해당 LOLBin 룰 → HIGH | T1218/T1486/T1567 |

**행동 패턴별 특징 분석.** 실험을 통해 ① *고속 암호화형*은 burst·엔트로피
신호가 한꺼번에 폭증해 수 초 내 CRITICAL에 도달, ② *저속 은닉형(stealth)*은
burst를 회피하지만 매직바이트 소실·확장자 변경은 피할 수 없어 결국 탐지됨,
③ *정상 프로세스 인젝션형*은 신뢰 게이트 면제를 노리나 카나리·지상 진실 신호가
면제 불가이므로 차단됨을 확인했다. `kill` 모드에서는 HIGH/CRITICAL 도달 시
커널 격리(후속 쓰기/rename 차단) + 프로세스 종료가 자동 수행되어 **추가 파일
암호화가 즉시 멈추는 것**을 postmortem 피해 집계로 검증했다.

## 6-3. 정상행위 실험 (정상 행위 미탐지 — 오탐 검증)

탐지 못지않게 중요한 것이 **정상 작업을 랜섬웨어로 오탐하지 않는 안정성**이다.
다음 정상 워크로드로 오탐 여부를 검증했다.

| 정상 작업 | 유발 가능 신호 | 오탐 억제 메커니즘 | 결과 |
|---|---|---|---|
| 대용량 압축(7-Zip/zip) | 고엔트로피 쓰기 | 매직 소실·확장자 변경·burst 미동반 → 단독 점수로 등급 미달 + 7-Zip 허용목록 | 미탐(정상) |
| 백업/동기화(Veeam/Acronis/OneDrive) | 대량 파일 I/O, rename | 운영자 허용목록(이름/경로) → 신호 면제 | 미탐(정상) |
| OS 유휴 작업(Defender 스캔, 서비싱, WMI 재빌드) | 대량 파일 변경 | 행위자 신뢰 게이트 → 점수 미반영 | 미탐(정상) |
| 정상 문서 다량 편집/저장 | 다수 modify 이벤트 | 윈도우 burst 임계(15/10초) 미달, 엔트로피 정상 | 미탐(정상) |
| 이름이 우연히 겹치는 텍스트(`README.txt`) | 협박문 이름 패턴 매칭 | 내용 미확인 → MEDIUM 힌트로만, 승격 안 함 | 미탐(정상) |

**안정성 평가.** 초기 버전은 유휴 머신에서 OS 작업만으로 CRITICAL 오탐이
발생했으나(커밋 `a203882` 이전), 행위자 신뢰 게이트 도입 후 유휴 상태 점수가
INFO로 안정화되었다. 또한 corroboration 기반 정밀 종료로 전환(커밋 `ab743d1`)하여
오탐 1건이 다수 정상 프로세스 종료로 번지는 위험을 제거했다. 순수 로직 영역은
**pytest 430개 케이스**로 회귀 검증하여, 임계치·가중치·신뢰 게이트·협박문 승격
규칙이 의도대로 동작함을 자동화 테스트로 보증한다. 특히 corroboration 정밀
종료 정책은 한 차례 리팩터링 중 실수로 되돌려졌던 이력이 있어, "보강 증거 없는
HIGH 는 기록만 한다"·"점수 기반 일괄 종료는 없다"는 정책 자체를 회귀 테스트로
고정했다(`tests/test_responder.py::TestCorroboratedKillPolicy`).

# 7. 결과

## 7-1. 과제 수행 결과

본 과제는 **실시간 행위 기반 랜섬웨어 탐지·차단 EDR**을 설계 목표대로 구현·검증
하는 데 성공했다.

- **신종 탐지 검증.** 시그니처 없이도 고속/저속/인젝션/LotL 등 다양한 공격
  시나리오를 행위 신호의 *조합과 강도*로 탐지하고, `kill` 모드에서 커널 격리 +
  프로세스 종료로 **추가 암호화 확산을 자동 차단**함을 확인했다. 특히 저속
  은닉형과 신뢰 프로세스 위장형 등 *기존 방식의 사각지대*도 매직바이트 소실·
  카나리·협박문 확산 같은 지상 진실 신호로 포착했다.
- **오탐 억제 검증.** 압축·백업·동기화·OS 유휴 작업 등 정상 워크로드를 3중 게이트
  (행위자 신뢰·허용목록·내용 검증)로 미탐 처리하여, 탐지율과 안정성의 균형을 달성.
- **운영·포렌식 완성도.** 커널 v2 드라이버(파일/프로세스/레지스트리/핸들보호),
  자기 보호(Critical 플래그·DACL·ObCallback·watchdog 상호 감시), MITRE ATT&CK
  매핑, Markdown 사건 보고서, SQLite 이벤트 스토어, Flask 대시보드, SIEM/Webhook
  통합까지 *탐지 그 이상의 EDR 운영 기능*을 구비.
- **정량 규모.** Python ≈ 13,000 LOC, 커널 C/H ≈ 1,450 LOC, 8종 탐지기,
  33개 명령어 룰, 430개 자동화 테스트.

→ 결론적으로, **다양한 랜섬웨어에 대해 효과적인 탐지 및 차단이 가능함**을 실험으로
검증하였으며, 행위 기반 접근이 시그니처 기반의 신종·제로데이 한계를 실질적으로
보완할 수 있음을 입증했다.

## 7-2. 한계점 및 개선점

| 한계점 | 내용 | 개선 방향 |
|---|---|---|
| **탐지 지연 동안의 초기 피해** | 행위 기반은 *행위가 발생한 후* 탐지하므로, 탐지·대응 이전에 암호화된 소수 초기 파일은 막을 수 없다(원리적 한계). | 커널 차단 반응 속도 최적화, write-on-first-access 사전 가로채기, 자동 롤백(VSS/백업 연계)을 통한 피해 복구 |
| **성능 부담** | 사용자 모드 폴링(psutil/엔트로피 샘플링)과 커널 이벤트가 고부하 시 자원을 소모, 일부 단명 프로세스를 WMI가 놓칠 수 있음. | 커널 콜백 비중 확대(이미 process/registry는 커널화), 엔트로피 샘플링 적응적 조절, 이벤트 배치 최적화 |
| **잔존 오탐 가능성** | 신규·미등록 정상 소프트웨어가 대량 암호화 유사 I/O를 일으키면 오탐 여지가 남는다. | 머신러닝 기반 행위 분류 보강, 허용목록 자동 학습, 평판/서명 연계 |
| **고급 회피 대응** | 매우 느린 암호화·합법 도구만 사용하는 극단적 LotL·BYOVD 커널 공격은 추가 대응 여지. | 누적·장기 윈도우 상관분석, 커널 무결성 보호 강화 |
| **제품화 격차** | 중앙 관리 콘솔(fleet)·RBAC/SSO·서명 MSI 자동배포·격리 보관소/원클릭 복구는 미구현(로드맵). | 관리 서버 + 정책 원격 푸시, SSO, 서명 패키징·단계적 롤아웃 |
| **플랫폼 한정** | 커널 기능은 Windows 11 전용. | 크로스플랫폼 사용자 모드 탐지 강화, macOS ESF/Linux fanotify 연계 |

**종합 개선 방향.** ① *예방*으로의 확장 — 탐지 후 차단을 넘어 자동 롤백·VSS
연계 복구로 피해를 0에 수렴, ② *지능화* — 휴리스틱에 ML 행위 분류를 결합해
오탐·회피 동시 개선, ③ *제품화* — fleet 관리·RBAC·서명 배포로 연구 프로토타입을
기업 제품 수준으로 격상하는 것을 향후 과제로 제시한다.
